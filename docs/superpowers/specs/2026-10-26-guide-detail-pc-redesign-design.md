# 가이드 상세 페이지 PC 개편 — 설계

작성일: 2026-10-26

## 왜 하는가

가이드 상세 페이지(`/guide/[songId]`, 같은 UI를 쓰는 `/slam/[songId]` 포함)를
**즛토마요를 전혀 모르는 사람**이 처음 열어도 "이 곡에서 언제, 무엇을 하면 되는지"
바로 알 수 있게 만든다. 지금은:

1. 가사 단락(1절/2절 등) 경계가 눈에 띄지 않는다.
2. 스윙·클랩·콜 아이콘이 무슨 뜻인지 화면 어디에도 설명이 없다(아이콘 `title` 툴팁뿐).
3. 영상이 화면 높이를 거의 다 차지해 설명을 붙일 자리가 없다.
4. 상세 화면에서 다른 곡으로 가려면 목록으로 돌아가야 한다(이전/다음 버튼뿐).
5. 응원 줄은 줄 전체에 색 배경이 깔려, 응원이 많은 곡은 화면이 알록달록해지고
   "어느 단어에서" 응원하는지는 글자색으로만 구분된다.

## 범위

- **PC 우선.** 태블릿 이상(`tablet:` = 800px+)의 2단(영상 | 가사) 레이아웃에 적용한다.
  지금 태블릿과 PC가 같은 구조를 공유하므로 둘을 함께 바꾼다(빌더 판단 — 아래 참고).
- **모바일(800px 미만)은 이번에 바꾸지 않는다.** 단, 데이터 변경(단락)과 가사 줄
  표시 방식(5번)은 공통 컴포넌트라 모바일에도 자연히 반영된다. 모바일 레이아웃
  (순서, 영상 크기, 버튼 위치)은 그대로 유지해야 한다.
- `/guide` 목록 화면(곡 선택 전)은 바꾸지 않는다.

### 하지 않는 것

- 영상 아래 "곡 설명/추가 콘텐츠"의 실제 내용 작성 — **자리만 확보**한다(사용자가 나중에 채움).
- 모바일 개편(다음 단계).
- 곡 목록 화면 디자인 변경.

### 실패로 볼 것

- 모바일 레이아웃이 깨지거나 바뀜.
- YouTube iframe이 곡 이동·패널 열고 닫기 때 다시 생성됨(재생 끊김) — 지금 구조가
  iframe을 언마운트하지 않으려고 max-height 트릭을 쓰는 이유를 유지할 것.
- 재생 중 가사 줄 리렌더 최적화(`LyricLine` memo)가 깨짐.
- 슬램 모드(`/slam`)가 깨짐 — 같은 컴포넌트를 쓰며 `visibleTags`만 다르다.

## 사용자가 정한 것

### 레이아웃: B안 (2단 유지 + 곡 목록은 버튼으로 열기)

```
┌───────────────────────────────────────────┬──────────────────────┐
│ [☰ 곡 목록]  [◀ 이전 곡]  [다음 곡 ▶]       │  가사 패널            │
│                                           │  ── 1절 ──            │
│        ┌─────────────────────┐            │  가사 줄…             │
│        │   YouTube (작게)     │            │  ── 2절 ──            │
│        └─────────────────────┘            │  …                    │
│  [응원 표시 안내: 🟢스윙 🔵클랩 🟠콜]       │                      │
│  [곡 정보 / 설명 — 자리만 확보]             │                      │
└───────────────────────────────────────────┴──────────────────────┘
```

- 영상 위(또는 영상 바로 위 한 줄)에 **곡 목록 / 이전 곡 / 다음 곡** 버튼.
- **곡 목록** 버튼을 누르면 화면 왼쪽에서 목록 패널(드로어)이 열린다. 곡을 고르면
  그 곡으로 이동하고 패널이 닫힌다.
- 영상은 지금보다 작게(현재 `min(90%, (100dvh-4rem)*16/9)`) 줄여서 아래 공간을 만든다.
- 영상 아래 **응원 표시 안내**(범례)를 항상 보여준다: 이 모드에서 보이는 태그
  (`visibleTags`)마다 아이콘 + 이름 + 한 줄 설명. 슬램 모드면 슬램만.
- 그 아래 **곡 정보 영역**: 제목(jp/kr/en) + 나중에 채울 설명용 빈 자리.

### 가사 단락 구분

- 단락 제목(예: "1절", "2절", "RAP")을 단락 첫 줄 위에 작은 머리글로 보여주고,
  단락 사이에 여백을 둔다.

### 응원 줄 표시: "B안 − 왼쪽 막대"

- 응원 줄에 **줄 전체 배경과 왼쪽 색 막대를 넣지 않는다.**
- 응원 설명(`cheer.text` / `slam`)은 가사 위에 **색 배지**로: 아이콘 + 종류 이름 + 설명.
- 실제로 응원하는 단어(데이터의 `**…**` 등 강조 마커, `LyricSegment.tag`)에만
  응원 색 **형광펜 배경**을 칠한다.
- 재생 중인 줄은 지금처럼 보라색 배경/테두리(`ztmy-dark` / `ztmy-purple`).

## 빌더 판단(사용자가 확인 안 함 — 문서 검토 시 확인용)

1. **적용 구간을 태블릿 이상으로.** 지금 태블릿·PC가 같은 2단 구조라 PC만 따로
   떼면 구조가 두 벌이 된다. 태블릿 폭에서 빽빽하면 범례를 줄바꿈 허용.
2. **곡 목록 드로어 위치/형태:** 화면 왼쪽에서 열리는 패널, 바깥 클릭·Esc로 닫힘,
   열릴 때 현재 곡이 보이도록 스크롤. 항목은 기존 목록처럼 jp 제목(851MkPOP) + kr 제목
   - 응원 아이콘. 검색칸은 넣지 않는다(곡 수가 50여 개라 스크롤로 충분 — 필요하면 나중에).
3. **상세 화면 가사 패널 위의 "선택된 곡 제목" 줄**(지금 SongList가 접히며 남기는 한 줄)은
   태블릿 이상에서 숨긴다 — 제목은 영상 아래 곡 정보 영역으로 옮겨 중복을 없앤다.
   목록 → 상세로 접히는 애니메이션은 모바일용으로 그대로 둔다.
4. **단락 데이터:** `LyricLine`에 선택 필드 `section?: string`을 추가하고, 그 줄부터
   새 단락으로 본다. 기존 곡 파일의 `//==== 1절 ====//` 형태 주석을 스크립트로 다음
   줄의 `section` 필드로 옮긴다(주석은 제거). 주석이 없는 곡은 단락 머리글이 없다 —
   대신 간주(`interlude`) 줄 앞뒤 여백을 키워 최소한의 구분을 준다.
   `origin/`(원본 백업), `not-yet/` 데이터도 같은 타입을 쓰므로 주석이 있으면 같이 옮긴다.
5. **강조 단어가 없는 응원 줄**(예: 해마성장통 인트로 "노래 끝까지 흔들기")은
   배지만으로 표시한다.
6. **범례 설명 문구:** 스윙 = "샤모지를 흔들어요", 클랩 = "샤모지로 박수", 콜 = "다 같이 외쳐요",
   슬램 = 기존 라벨 기반 한 줄. `CallIcon`의 `ICON_LABEL`과 이름을 맞춘다.
7. **스윙 예시 GIF**(`SwingGuideGif`)는 지금 동작(스윙 구간에서 표시) 그대로 두고 위치만
   영상 영역 안에서 깨지지 않게 맞춘다.

## 남은 결정(빌더에게 맡김)

- 영상의 정확한 축소 비율, 각 영역 간격, 배지/형광펜의 정확한 색 농도.
- 드로어 애니메이션 방식.
- 범례·곡 정보 영역 컴포넌트 이름과 파일 배치(`src/features/guide/components/`).
