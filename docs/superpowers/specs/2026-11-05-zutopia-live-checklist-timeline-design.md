# 즛토피아: 라이브 성불 체크리스트 · 마지막 라이브 · 활동 연혁

## 배경과 의도

즛토피아(`/zutopia`)에는 곡·앨범(디스코그래피)과 공연(세트리스트 포함) 데이터가 이미 Supabase에 있다. 지금은 이 데이터를 **보기만** 할 수 있다. 이번 작업은 같은 데이터를 엮어서 팬이 "나와 즛토마요의 라이브 기록"을 보고 공유하게 만드는 것이다.

- **라이브 성불 체크리스트**: 내가 실제로 간 공연일을 체크하면 들은 곡과 횟수, 아직 못 들은 곡(=미성불)이 나오고, 이를 예쁜 이미지로 저장해 SNS에 올릴 수 있다. "성불"은 그 곡을 라이브로 들어 소원을 이뤘다는 팬 용어다.
- **디스코그래피 마지막 라이브**: 곡마다 마지막으로 불린 공연·날짜·총 횟수를 보여 준다. "요즘 이 곡 안 부르네"를 확인하는 용도.
- **활동 연혁**: 곡 발매·앨범 발매·공연을 시간 축 하나에 늘어놓아 활동 흐름을 한눈에 본다.

## 작업 순서 (각각 독립 커밋 단위)

0. R2 이미지 같은 출처 프록시 (HTTP/3 + 이미지 저장용 CORS 해결)
1. 세트리스트 영어 제목 표시
2. 디스코그래피 마지막 라이브 표시 + "최근 공연일 순" 정렬
3. 라이브 성불 체크리스트 (결과·못 들은 곡·이미지 저장·백업/복원)
4. 활동 연혁 (내 참전 표시 포함, 확대/축소는 이후)

2가 3의 "노래별 마지막 라이브 보러가기" 링크 대상이고, 4의 참전 표시는 3의 저장 데이터를 읽으므로 이 순서를 지킨다.

## 공통 제약

- `output: "export"` 완전 정적 사이트. Supabase 조회는 **빌드 타임에 서버 컴포넌트(`page.tsx`)에서만** 하고 결과를 props로 클라이언트 컴포넌트에 넘긴다(`docs/RULES.md` — `createBuildTimeSupabaseClient`). 런타임 API 없음.
- 사용자 데이터(체크 내역)는 전부 브라우저에만 저장. 서버 저장·로그인 없음.
- 모바일은 `body`가 스크롤되지 않는 구조다. 새 페이지는 내부 컨테이너 스크롤 + 중간 flex 체인의 `min-h-0`을 지킨다(`docs/RULES.md`).
- UI 방향(사용자 피드백): 모던·심플. 한쪽만 색칠된 강조 바, 그라데이션 버튼, 알약(pill) 모양 금지. 읽거나 누르는 글자는 최소 `text-sm`, 10px 글자 금지.
- 색 토큰은 `globals.css`의 `ztmy-*` 사용. 아이콘은 `src/components/icons/` 커스텀 SVG(외부 아이콘 라이브러리 금지).
- 한글 폰트는 서브셋이라, Supabase에서 오는 드문 한글 음절이 빠지면 `pnpm build`의 postbuild 검사가 실패한다 → `scripts/subset-fonts.mjs`의 `EXTRA_HANGUL`에 추가.
- 기존 공연 데이터 규칙을 재사용한다: 투어 공연일 세트리스트 = 투어 공통 곡 + 공연일 선택곡 병합(`lives/data.ts`의 `mergeTourSetlist`/`collapseRepeatedDays`), 투어 소속 판정(`tourDateFilter`), `live_date`는 `timestamptz`라 `"T"` 앞만 잘라 쓴다.

## 공통 데이터: 곡별 라이브 기록

2·3·4가 모두 "어느 공연(일)에서 어떤 곡이 불렸나"를 쓴다. 빌드 타임에 한 번 만드는 공용 데이터 모듈을 두고 셋이 같이 쓴다.

- **공연 단위(= 체크 단위)**: 실제로 열린 하루하루의 공연. 사용자는 "실제로 간 공연일을 하나씩" 체크하길 원한다.
- **실제 데이터 모양 (2026-11-05 조회, `lives` 24행 · `setlists` 247행)** — 규칙은 이 모양에 맞춰 정했다:
  - 투어(`tour_id` 있음, 전부 `type = CONCERT`) 공연일 행의 상당수가 `start_date`~`end_date` 이틀짜리다. 그중 일부는 자기 세트리스트 행에 `day_number` 1/2가 있고, 일부(예: 2026-02-28~03-01)는 `day_number` 없는 행만 있다(양일 선택곡이 같음).
  - 투어 아닌 `CONCERT`도 이틀짜리가 있다(INTENSE IN SEOUL은 `day_number` 1/2 있음, LEGACY ZOMBIE LABO 10-10~10-11은 없음).
  - `FESTIVAL`은 `start_date`~`end_date`가 페스티벌 전체 기간이고, `live_date`가 즛토마요 출연일이다.
  - `live_date`는 페스티벌·이벤트에만 있고 `CONCERT`는 전부 null.
  - 지난 투어 공연일은 모두 자기 세트리스트 행(선택곡)이 1개 이상 있다.
- **나누는 규칙** *(내 판단 — 위 데이터 기준)*:
  - `FESTIVAL`: 행 하나 = 공연 단위 하나. 날짜 = `live_date`(없으면 `start_date`).
  - `CONCERT`·`EVENT`: `start_date`부터 `end_date`(없으면 `start_date`)까지 **하루마다 공연 단위 하나**. DAY N 날짜 = `start_date + (N−1)일`. 그날 세트리스트 = (투어면 투어 공통 곡) + 이 행의 `day_number` 없는 곡 + `day_number = N`인 곡. `day_number`가 없는 이틀짜리 행은 양일 같은 세트리스트로 본다.
  - 투어 공연일에 자기 행이 하나도 없으면 투어 공통 곡만으로 센다(투어 공통 세트리스트는 매 공연 부른 곡이라는 뜻이므로). 현재 데이터엔 해당 없음.
  - 기존 `collapseRepeatedDays`는 표시용으로 일차를 합치는 함수라 집계에 쓰면 안 된다 — 합치기 전 원본 행으로 날짜별 목록을 만든다. 같은 날 같은 곡이 두 번 들어간 행(입력 실수)은 그날 1회로 센다.
  - 공연 단위 ID = `"<lives.id>:<YYYY-MM-DD>"`(날짜 기준). `day_number` 유무가 나중에 바뀌어도 사용자의 저장된 체크가 어긋나지 않게 하려는 것.
- **곡 단위 (어레인지 처리)** *(내 판단)*: 집계는 **원곡 기준**으로 한다.
  - 세트리스트가 어레인지 버전 곡(`original_song_id` 있음)을 가리키면 원곡으로 합산(현재 1행).
  - `setlists.note.arrange`(라이브 편곡 표기, 현재 14행)는 원곡 연주로 센다.
  - 디스코그래피에서 어레인지 버전 곡 행은 원곡과 같은 라이브 기록을 보여 준다. "못 들은 곡"·결과 목록에는 원곡만 나온다(어레인지 버전 곡은 따로 나열하지 않음).
- **미래 공연 제외**: 공연 단위 날짜가 빌드 날짜 이후면 집계·체크 목록에서 뺀다.
- **곡별 파생값**: 총 라이브 횟수(공연 단위 기준), 마지막 공연 단위(이름·날짜·상세 링크).

## 0. R2 이미지 프록시

**왜**: R2 커스텀 도메인 `assets.ztmy-sounds.fans`는 `alt-svc: h3`를 안 보내 HTTP/2로만 받아지고(메인 도메인은 h3 광고함), CORS 헤더도 없어 3단계의 이미지 저장(canvas)이 막힌다(2026-11-05 `curl -I`로 확인). 메인 도메인 아래 경로로 프록시하면 같은 출처가 되어 둘 다 해결된다.

- **Pages Function**: `functions/r2/[[path]].ts` — `/r2/<경로>` → `https://assets.ztmy-sounds.fans/<경로>`로 GET/HEAD만 전달. 응답에 긴 `Cache-Control`(R2 파일은 내용이 바뀌면 이름도 바뀐다고 보고 `immutable` 수준 — builder가 R2 운영 방식 확인 후 결정).
  - **`/assets/` 접두사는 쓰지 않는다**: `public/assets/`(로고·가이드·공지 등 정적 파일)와 겹치고, Pages에선 Function이 정적 파일보다 먼저 잡혀 기존 이미지가 깨진다. (사용자가 가져온 가이드 문서는 `/assets/`를 썼지만 이 이유로 `/r2/`로 바꿈.)
  - `wrangler pages deploy out`은 루트의 `functions/`를 함께 배포한다. `_routes.json`으로 Function 범위를 `/r2/*`로 한정해 다른 요청이 Function을 거치지 않게 한다.
- **URL 변환**: DB(`cover_image_url`, `poster_image_url`, `icon_image_url`, `additional_image_urls` 등)에는 절대 주소가 들어 있다. DB는 고치지 않고, 빌드 타임 데이터 계층에서 함수 하나(예: `toAssetUrl`)로 `https://assets.ztmy-sounds.fans/...` → `/r2/...`로 바꾼다. 하드코딩된 같은 도메인 주소가 코드에 있으면 함께 치환.
- **개발 환경**: `next dev`는 Pages Functions를 실행하지 않는다 → 개발에선 원래 절대 주소를 그대로 쓰고, 프로덕션 빌드에서만 `/r2/`로 바꾼다(환경 변수나 `NODE_ENV` 기준, builder 판단).
- **비용 주의**: 이미지 요청마다 Function 1회 호출 → Workers 무료 한도(하루 10만 요청)에 잡힌다. 긴 캐시 헤더로 재방문 요청을 줄인다. `RULES.md`에 기록.
- **PWA**: 서비스워커(`defaultCache`) 런타임 캐시가 `/r2/` 이미지를 같은 출처 이미지로 캐시하게 되는지 확인.
- **확인**: 배포 후 개발자 도구 Network 탭에서 `/r2/` 이미지 프로토콜이 `h3`, 기존 `/assets/` 정적 이미지가 그대로 뜨는지.

## 1. 세트리스트 영어 제목

- 공연 상세·투어 상세의 세트리스트(`lives/Setlist.tsx`, `SongLink.tsx`)에 지금 원어 + 한국어만 나온다 → 영어 제목(`songs.title_en`)도 표시.
- `LiveSetlistEntry`에 `titleEn` 추가, `lives/data.ts`의 setlist 조회에 `title_en` 포함.
- 배치(원어/한국어/영어 세 줄 vs 한국어 옆 영어)는 builder 판단. 디스코그래피 앨범 헤더가 PC에서 한국어 왼쪽·영어 오른쪽으로 두는 방식이 참고가 된다. 모바일에서 행이 너무 높아지지 않게.

## 2. 디스코그래피: 마지막 라이브

대상: 곡 목록 `/zutopia/songs` (`song-db/components/SongListView.tsx`).

- **켜기**: 필터 카드의 "보기" 줄(`FilterRow label="보기"`, 지금 미발매 숨기기가 있는 곳)에 "마지막 라이브" 체크 추가. *(내 판단)*
- **표시 (체크 켠 상태)**: 곡 행의 **제목 아래에 한 줄 추가**(사용자 선택: B안). 발매일 등 기존 오른쪽 칸은 그대로.
  - 형식: `마지막 · <공연명(링크)> · <YYYY.MM.DD> · 총 N회 · N일 전`
  - 라이브 기록 없는 곡: "라이브 기록 없음"(흐린 글자).
  - "N일 전"은 빌드 날짜가 아니라 **보는 시점(클라이언트) 기준**으로 계산. *(내 판단 — 정적 빌드가 오래 남으면 빌드 기준은 틀어짐)*
  - 공연명 링크: 해당 공연 상세. 투어 공연일이면 그 투어 상세 페이지. *(내 판단)*
- **정렬 "최근 공연일 순"**: 기존 정렬 옵션(앨범·발매일)에 추가. 마지막 라이브 체크가 켜져 있을 때만 옵션이 보인다. *(내 판단)* 기존 오름/내림 전환을 그대로 쓴다(내림 = 최근 공연 먼저, 오름 = 오래 안 부른 순). 기록 없는 곡은 방향과 상관없이 맨 뒤. 이 정렬에선 앨범·연도 그룹 헤더 없이 한 목록. *(내 판단)*
  - 체크를 끄면 정렬이 이 옵션이었을 경우 기본 정렬(앨범)로 돌아간다.
- **주소로 켜기**: `?lastLive=1`이면 체크된 상태로 시작. 체크를 켜고 끌 때 주소에도 반영(`router.replace`). 기존 `?song=`/`?album=` 파라미터와 공존해야 한다. *(내 판단)*
- **곡 상세 패널**(`SongDetailPanel`): 체크와 상관없이 마지막 라이브·총 횟수를 항상 표시. *(내 판단, 사용자에게 제안함)*

## 3. 라이브 성불 체크리스트

### 위치

새 페이지(예: `/zutopia/checklist`). 헤더 내비(`zutopia/nav.ts`의 `ZUTOPIA_NAV_ITEMS`)에 "성불" 추가. 허브 카드(`registry.ts`)에 넣을지는 builder 판단 — `ZUTOPIA_CATEGORIES`는 `getEntries` 기반 목록형 카테고리용이라 맞지 않으면 nav만 추가. *(경로·라벨은 내 판단)*

### 화면: 탭 두 개 (사용자 선택: B안)

**① 간 공연 고르기**

- 모든 공연 단위를 최신순으로 나열. 투어는 투어 이름 아래에 공연일들을 묶어 보여 주고(펼침/접힘은 builder 판단), 투어 아닌 공연은 그대로 한 줄.
- 한 줄 = 체크박스 + 날짜 + 도시/공연명 + (일차가 있으면 DAY N). 체크하면 즉시 저장.
- 상단에 체크한 공연 수.

**② 내 성불 결과**

- 상단 숫자: 간 공연 수, 들은 곡 수, (제안) 못 들은 곡 수.
- "들은 곡 / 못 들은 곡" 두 목록.
  - 들은 곡: 곡별 들은 횟수. 정렬 = 횟수 많은 순 → 같으면 발매일 순. *(내 판단)*
  - 못 들은 곡: 전체 **발매곡** 중 한 번도 못 들은 곡(미발매곡 제외). 정렬은 발매일 순. *(내 판단)*
- 곡 한 줄: 커버 + 일본어/한국어/영어 제목 + 횟수.
- 버튼:
  - **이미지 저장** (아래)
  - **노래별 마지막 라이브 보러가기** → `/zutopia/songs?lastLive=1`을 **새 창**(`target="_blank"`)으로 연다.
  - **백업 / 복원** (아래)
- 체크 0개일 때 결과 탭: 빈 상태 안내 + ① 탭으로 가는 안내.

### 저장 (로컬)

- `localStorage` 한 키에 JSON. IndexedDB는 쓰지 않는다(데이터가 작고 동기 접근이 편함). *(내 판단)*
- 형식 예: `{ version: 1, attended: ["<공연 단위 ID>", ...], updatedAt: "<ISO>" }`.
- 정적 빌드라 처음 그릴 때는 저장값을 모른다 → 하이드레이션 후 읽어서 반영(서버 HTML과 첫 렌더 불일치 방지).
- 저장된 ID가 지금 데이터에 없으면(공연 삭제 등) 조용히 무시하되 지우지는 않는다.

### 백업 / 복원

- 백업: 위 JSON을 파일로 내려받기(예: `ztmy-checklist-YYYYMMDD.json`).
- 복원: 파일 선택 → 형식 검사 → 현재 체크 내역을 **덮어쓸지 확인** 후 적용. *(덮어쓰기 vs 합치기는 내 판단: 덮어쓰기 + 확인)*
- 공유 링크 방식은 이번 범위 아님.

### 이미지 저장

**형태**

- PC(화면 너비 ≥ 사이트 `tablet` 브레이크포인트, 50rem): **정사각형** 기본. 모바일: **9:16 세로** 기본. 저장 버튼 옆에 "정사각형 / 세로" 전환. 둘 다 곡 목록 **2열**. *(전환 버튼·세로 2열은 내 판단)*
- 출력 해상도: 정사각형 1080×1080, 세로 1080×1920 정도. *(내 판단)*

**디자인 (사용자 확정)**

- 배경: 사이트 배경색(`#050223`) 단색 + 이미지 가장자리 **흰 테두리**. (배경 이미지 블러안은 탈락.)
- 상단 가운데 정렬: 사이트 로고(`/assets/logo/ztmy-sounds-logo.webp`, **흰 외곽선** — `MobileHeader.tsx`와 같은 1px drop-shadow 4방향 방식) → 제목("나의 ZUTOMAYO 라이브 성불 기록" 정도, 문구는 builder 판단) → 숫자(간 공연 수, 들은 곡 수).
- 곡 한 칸: **앨범 커버** + **일본어 / 한국어 / 영어 제목** + 횟수.
- 횟수 표기: **탤리(세로줄 4개 + 사선 1개 = 5회 한 묶음)**, 색은 `ztmy-magenta`(또는 `ztmy-pink`, builder가 대비 보고 선택). 획은 폰트가 아니라 SVG로 직접 그린다. 남는 횟수는 그 개수만큼 세로줄. 5회 묶음 4개(20회)를 넘으면 그 뒤는 "+N"으로 줄인다. *(+N은 내 판단)*
- 하단: 공연 기간(첫 공연 ~ 마지막 공연), 사이트 주소 `ztmy-sounds.fans`.
- 이미지에는 **들은 곡만** 들어간다(못 들은 곡은 화면에서만). *(내 판단)*
- 정렬: 결과 화면과 같음(횟수 많은 순 → 발매일 순).

**곡 수에 따른 크기 (사용자 확정 원칙: 전부 한 장에 넣는다)**

- 곡 수에 따라 커버·글자·간격을 단계적으로 바꾼다. 곡이 적으면 크고 넉넉하게(사용자가 시안이 "너무 작고 빽빽하다"고 지적함 — 여유를 우선).
- 정해 둔 최소 크기까지 줄여도 넘치면 **간단한 모드**: 커버 + 일본어 + 한국어(영어만 뺌). 일본어 + 한국어는 어떤 경우에도 남긴다.
- 단계 경계값(몇 곡에서 바꿀지)과 최소 글자 크기는 builder가 실제 렌더링으로 정한다. 최소 크기에서도 1080px 이미지 기준으로 폰 화면에서 읽을 수 있어야 한다.

**구현 메모 (builder 판단 + 확인 필요)**

- 클라이언트에서 DOM/SVG → PNG로 만든다. 방식(라이브러리 `html-to-image` 등 추가 vs 직접 SVG `foreignObject`/canvas)은 builder 판단. 새 의존성을 넣으면 `docs/STACK.md`에 기록.
- **커버 이미지 CORS**: 0단계 프록시로 커버가 같은 출처(`/r2/...`)가 되어 해결된다. 단 개발 환경은 절대 주소라 canvas 저장이 CORS로 실패할 수 있다 — 개발 중 이미지 저장 확인 방법(예: 프로덕션 빌드를 `wrangler pages dev out`으로 띄우기)을 builder가 정한다. 커버가 없는 곡(null)은 앨범 커버 → 기본 자리 표시로 대체(`getSongCoverSrc`와 같은 순서).
- 웹폰트(LINE Seed KR/JP)가 이미지에 그대로 들어가야 한다(서브셋 폰트 포함 여부, 폰트 로드 완료 후 캡처).
- 모바일(특히 iOS 인앱 브라우저)에서 다운로드가 막히면 Web Share API(`navigator.share` 파일 공유)로 대체. *(내 판단)*

## 4. 활동 연혁

### 위치

새 페이지(예: `/zutopia/timeline`). 헤더 내비에 "연혁" 추가. *(내 판단)*

### 담는 일정 (사용자 확정: 세 종류만)

- 곡 발매(`songs.release_date`), 앨범 발매(`albums.release_date`), 공연.
- 공연: 투어는 첫 공연일~마지막 공연일 **기간 막대**, 투어 아닌 공연·페스티벌은 **점**. *(내 판단)*
- MV 공개·타이업 등 그 밖의 일정은 데이터가 없어 이번 범위 아님.
- 미발매곡은 날짜가 없거나 의미가 없으면 제외(데이터 확인 후 builder 판단).

### 화면 (사용자 확정)

- **PC**: 가로 한 줄 시간 축. 좌우 스크롤. 간격은 **실제 시간에 비례**.
- **모바일**: 같은 타임라인을 **세로 축**으로 돌린다. 위아래 스크롤, 간격은 실제 시간에 비례, 라벨은 축 옆에 표시.
- 색: 곡 `ztmy-sky`, 앨범 `ztmy-sun`, 공연 `ztmy-purple`. *(내 판단)*
- **내 참전 표시**: 성불 체크리스트에서 체크한 공연은 `ztmy-magenta` 테두리로 강조(로컬 저장값을 읽음, 하이드레이션 후).
- 라벨 겹침(PC): 겹치는 라벨은 숨기고 마우스 올림/포커스 시 표시. *(내 판단)*
- 범례(곡/앨범/공연)를 눌러 종류별로 켜고 끄기. *(내 판단)*
- 처음 열면 가장 최근 일정이 보이는 위치. *(내 판단)*
- 일정 누르기: 곡 → `/zutopia/songs?song=<slug>`(기존 상세 패널), 앨범 → `/zutopia/albums`의 해당 앨범 상세, 공연 → 공연(투어) 상세 페이지. *(내 판단)*
- 같은 날 일정 여러 개(예: 앨범과 수록 싱글 동시 발매)는 겹치지 않게 쌓는다.

### 확대/축소 (이후로 미룸)

- 이번엔 구현하지 않는다. 다만 위치 계산을 "날짜 → 픽셀 = (날짜 − 시작일) × 배율" 하나의 함수로 두어, 나중에 배율만 바꾸면 되게 만든다.

## 목표 / 비목표 / 실패 기준

**목표**: 위 네 단계가 각각 동작하고, 3에서 만든 이미지를 받은 사람이 "이 사람이 무슨 곡을 몇 번 들었는지" 한눈에 읽을 수 있다.

**비목표**: 로그인·서버 저장·기기 간 동기화, 공유 링크, 연혁 확대/축소, 새 일정 종류(MV 등) 데이터 입력, 다른 사람과 기록 비교.

**실패로 보는 경우(동작은 해도)**:

- 투어 공연일·일차별 선택곡이 집계에 반영되지 않거나 이중으로 세어진다.
- 이미지가 곡이 많을 때 읽을 수 없을 만큼 작아지거나, 곡이 적을 때 빽빽하다.
- 체크 내역이 새로고침·재방문에 사라진다.
- 모바일에서 페이지 전체(`body`)가 스크롤된다.
