# 투어 상세 — 한 눈에 보이는 세트리스트·일정 (2026-11-26)

## 의도

투어 상세(`/zutopia/lives/<투어 slug>`)에 들어오면 **공통 세트리스트와 공연 일정이 처음부터
펼쳐진 채 한 화면에** 보이고, 공연일별 상세 세트리스트는 궁금할 때만 눌러서 본다. 지금은
공통 세트리스트가 접힌 카드("투어 세트리스트 한 눈에 보기")이고, 공연일은 일정 목록 안에서
아코디언으로 펼쳐져 같은 곡이 페이지에 두 번 나오며 페이지가 길다. PC의 티켓(투어 기간·
공연 횟수)도 쓸데없이 크다.

## 목표

- PC: 티켓 아래 **좌우 2단** — 왼쪽 세트리스트 패널, 오른쪽 공연 일정. 처음엔 왼쪽이 공통
  세트리스트(펼친 상태).
- 일정의 **날짜 줄을 누르면 왼쪽 패널이 그날 세트리스트로 바뀐다**(일정 안 아코디언은 없앤다).
- 공통 세트리스트 상태에서 판이 둘 이상이면 **전반기·중반기·후반기 탭**, 변경점은 지금처럼
  **도장**(SetlistChangeLine, setlist-diff.ts)으로.
- **세트리스트 비교하기**: 공연일 두 개를 골라 전후를 나란히 비교하는 창.
- 고른 공연일은 **주소 해시**에 남는다 — 링크 공유·새로고침·뒤로 가기가 그대로 동작.
- 모바일·태블릿: 위아래로 쌓고, 날짜를 누르면 **아래에서 올라오는 시트**로 그날 세트리스트.
- 티켓: 지금의 보딩 티켓 디자인(절취선·위 색 띠·LISTEN/POST 줄)을 그대로 쓰되 PC에서 낮게.

## 하지 않는 것

- 단독 공연 상세(DefaultLiveContent — 이틀 이상 공연의 DAY별 일정 LiveSchedule)는 그대로
  둔다. 이번 변경은 투어 상세만.
- 데이터·조회(getTourBySlug, TourDetail 타입)는 바꾸지 않는다 — 화면만.
- 3개 이상 동시 비교, 판끼리 비교 창(판 차이는 이미 도장으로 보인다).

## 실패로 치는 것(동작은 해도)

- 처음 들어왔을 때 세트리스트나 일정 어느 한쪽이 접혀 있거나 PC에서 둘이 한 화면에 안 보임.
- 날짜를 눌렀는데 무엇이 바뀌었는지 모름(어느 날의 세트리스트인지 표시가 없음).
- 모바일에서 날짜를 열고 닫을 때 일정 목록 스크롤 위치를 잃음.
- 글자가 작아짐(text-sm 미만), 한쪽 테두리 강조선·그라데이션 버튼·알약 모양 등장
  (사용자 UI 선호 — 메모리 feedback_font_size_minimum, feedback_ui_style_direction).

## 고른 방식

검토한 방식:

1. **화면 안 상태만** — 고른 날짜는 컴포넌트 state. 가장 단순하지만 새로고침·공유 시 공통으로
   돌아가고, 모바일 시트를 뒤로 가기로 닫을 수 없다.
2. **주소 해시에 고른 날짜(채택)** — 1에 해시 읽기·쓰기만 더한다. 특정 공연일 세트리스트
   링크를 공유할 수 있고 뒤로 가기가 자연스럽다. 정적 export라 서버 쪽 변화는 없다.

레이아웃은 시안 A(좌우 2단)를 골랐다. B(1단 + 세트리스트 2열)는 일정이 여전히 아래에 있어
한 화면에 안 들어오고, C(일정을 선택곡 열로 된 표)는 모바일에서 가로로 넘친다.

## 설계

### 페이지 구성 (DefaultTourContent)

모바일·태블릿: 지금처럼 포스터 → 추가 이미지 → 제목 → **티켓(compact)** → **TourOverview**
(새 클라이언트 컴포넌트). 지금의 `TourSetlistVersions` + `LiveSchedule` 두 덩어리를 TourOverview
하나로 바꾼다.

PC(`pc:` 1080px 이상)는 들어오자마자 2단이 보이게 **머리 부분을 한 줄로**(사용자 결정):

```text
┌────────┐  즛토마요
│ 포스터 │  투어 제목 / TOUR TITLE
│ (중간) │  [ 티켓(compact) — 기간 · 횟수 · LISTEN … ]
└────────┘  (추가 이미지 썸네일 줄)
┌ 세트리스트 패널 ──────┐ ┌ 공연 일정 ──────────┐
```

- 왼쪽 포스터는 중간 크기(높이 약 280px, 구현자 판단), 누르면 ZoomableImage로 크게. 목록에서
  들어올 때의 ViewTransition(posterTransitionName)은 그대로 이 포스터에.
- 오른쪽에 제목(왼쪽 정렬)·티켓·추가 이미지. 포스터가 없으면 오른쪽 덩어리만 전체 폭.
- 페이지 폭은 한 단계 넓힌다(지금 `pc:max-w-4xl` → `pc:max-w-6xl` 정도, 구현자 판단).

### 티켓 (LiveTicket)

`compact` 옵션(기본 false)을 더한다. 켜면 PC(`tablet:` 이상)에서 맨 위 종류 줄과 칸(cells)을
한 줄에 놓고 칸 세로 여백·값 글자를 줄인다 — 절취선·색 띠·LISTEN/POST/OFFICIAL 줄 디자인은
그대로. 모바일은 지금과 같다. 투어 상세만 compact, 공연 상세는 지금 그대로.

### TourOverview — 상태

- `selectedDateId: string | null` — null이면 공통 세트리스트. 값은 TourDateEntry.id.
- `versionId` — 공통 세트리스트의 판 탭(지금 TourSetlistVersions의 state).
- `compareOpen`, 비교의 `compareA`·`compareB`(공연일 id).
- 해시 동기화: 고른 날짜 ↔ `location.hash`.
  - 해시 값은 사람이 읽을 수 있게 **공연 날짜 `YYYY-MM-DD`**. 같은 날짜의 공연일이 둘 이상이면
    (하루 여러 회차·같은 날 두 도시) 두 번째부터 `-2`, `-3`(목록 순서대로).
  - 날짜를 고르면 `history.pushState`로 해시를 바꾸고(뒤로 가기 = 이전 선택), 공통으로 돌아가면
    해시를 비운다. `hashchange`/`popstate`로 상태를 맞춘다. 처음 로드 때 해시가 있으면 그 날짜를
    고른 상태로 시작(모바일이면 시트를 연 채로). 모르는 해시는 무시.
  - 취소된 공연일은 고를 수 없다(지금처럼 누를 수 없음).
- 시트로 볼지 왼쪽 패널로 볼지는 `matchMedia("(min-width: 67.5rem)")`(pc 기준)로 정한다 —
  고른 날짜 state는 하나라 창 폭을 바꾸면 시트 ↔ 왼쪽 패널로 자연스럽게 옮겨 간다(내 판단).
- 판 탭은 날짜를 골랐다가 공통으로 돌아와도 그대로(고른 날짜의 판으로 바꾸지 않음, 내 판단).
- 정적 export라 첫 렌더(서버)는 해시를 모른다 — 공통 세트리스트로 그리고 하이드레이션 뒤
  해시를 읽는다(깜빡임은 PC 왼쪽 패널 내용 교체 정도로 허용).

### PC 레이아웃 (`pc:` 이상)

```text
[ 티켓(compact) ─────────────────────────────────────────────── ]
┌ 왼쪽: 세트리스트 패널 ──────────┐ ┌ 오른쪽: 공연 일정 ──────────┐
│ (공통) 투어 세트리스트 15 songs │ │ 공연 일정            13 dates │
│        [세트리스트 비교하기]    │ │ 오사카 大阪 · 공연장          │
│ [전반기][중반기][후반기]        │ │  04.20 THU 선택 正義 …  14곡 ▸│
│ 01 グラスとラムレーズン         │ │  04.21 FRI 선택 …       14곡 ▸│
│ 05 またね幻  (도장: 중반기부터) │ │ 나고야 …                      │
│ 07 선택곡 正義 · 勘ぐれい …     │ │                               │
└─────────────────────────────────┘ └───────────────────────────────┘
```

- 두 칼럼 비율은 대략 반반(구현자 판단). 왼쪽 패널은 **sticky**(위 여백 두고)로 일정을 길게
  내려도 세트리스트가 화면에 남게 한다 — 패널이 화면보다 길면 패널 안 스크롤.
- **공통 상태**: 지금 TourCommonSetlist 내용 그대로(판 탭·도장·선택곡 자리 줄), 단 접기 없음
  (collapsible 끔), 제목은 "투어 세트리스트". 제목 줄 오른쪽에 "세트리스트 비교하기" 버튼.
  선택곡 자리 줄의 도시 목록은 그대로 둔다(줄 수가 많으면 구현자가 줄여 보여도 됨 — 예: 3개까지와
  "외 n").
- **날짜 상태**: 패널 머리에 "← 투어 세트리스트" 버튼, 그날 도시·날짜(요일)·DAY/회차·공연장,
  작은 포스터 썸네일(누르면 ZoomableImage로 크게 — 추가 이미지도 같은 묶음). 아래는 지금
  TourDatePanel의 `<Setlist entries={date.setlist} plain />`과 같은 그날 세트리스트(선택곡 강조
  그대로). 세트리스트가 없으면 "세트리스트가 곧 업데이트됩니다." 판 탭은 숨긴다.
  비교하기 버튼은 날짜 상태에도 둔다(A = 그날로 열림).
- **오른쪽 일정**: 지금 TourDateList의 도시 머리·날짜 줄 모양 그대로, 아코디언 펼침
  (TourDatePanel)만 없앤다. 날짜 줄 오른쪽 꺾쇠는 아래(▾)가 아니라 오른쪽(▸) — 펼치는 게
  아니라 옆에서 열린다는 표시. 고른 날짜 줄은 강조(지금 펼친 날의 분홍 날짜 + 옅은 면).
  도시 머리를 누르면 그 도시 첫 공연일을 고른다(취소 제외). 일정이 아직 없으면 지금 안내 문구.
- **공통 세트리스트가 없는 투어**(공통 행이 없음): 날짜를 고르기 전 왼쪽 패널엔 "날짜를 고르면
  그날 세트리스트가 여기에 나와요" 같은 짧은 안내. 공연일도 없으면 2단 없이 일정 안내 문구만
  전체 폭(내 판단).

### 모바일·태블릿 (`pc:` 미만)

- 위아래로 쌓는다: 티켓 → 투어 세트리스트(공통 상태, 펼친 채, 판 탭·도장·비교하기 버튼) →
  공연 일정.
- 날짜 줄을 누르면 **SidePanel**(모바일 아래 시트, 태블릿은 오른쪽 패널 — 기존 컴포넌트 동작)로
  그날 세트리스트를 연다. 시트 제목 = 도시, subtitle = 날짜·DAY·공연장, 내용 = PC 날짜 상태와
  같은 썸네일 + 세트리스트. 시트를 닫으면 해시를 비운다(뒤로 가기로 닫아도 됨). 일정 목록
  스크롤 위치는 그대로.
- 공통 세트리스트는 PC처럼 고른 날짜로 바뀌지 않는다(시트로만 본다).

### 세트리스트 비교하기

- **SidePanel `size="wide"`**로 연다(PC 오른쪽 넓은 패널, 모바일 아래 시트). 제목 "세트리스트 비교".
- 위에 공연일 고르기 두 개(A·B) — 일정과 같은 순서의 목록에서 고른다(도시 + 날짜 + DAY/회차,
  취소·세트리스트 없는 날 제외). 기본값: 날짜를 고른 상태면 A = 그날, B = 그 바로 앞 공연일
  (첫 공연일이면 다음 공연일). 공통 상태에서 열면 A = 첫 공연일, B = 마지막 공연일.
  고르기 UI 모양은 구현자 판단(네이티브 select 또는 목록 — text-sm 이상, 알약 금지).
- 아래에 두 세트리스트를 **나란히 두 칼럼**(모바일도 두 칼럼, 제목 한 줄 말줄임) — 번호·제목.
  차이 표시: A에만 있는 곡 = "빠짐", B에만 있는 곡 = "추가", 둘 다 있는데 순서가 바뀐 곡 =
  "순서 변경"(A n번 → B m번). setlist-diff.ts의 LCS 매칭(곡 id 기준)을 날짜 두 개에 쓸 수 있게
  일반화한다 — 지금 diffSetlistVersions는 판 이름 문구("후반기부터")에 묶여 있으니, 매칭 결과
  (추가·제거·이동 목록)를 내는 함수와 문구를 만드는 부분을 나눈다. 같은 곡은 가로로 같은 줄에
  맞추지 않아도 된다(두 목록 각각 번호 순, 차이 곡만 표시) — 구현자가 더 나은 정렬이 쉬우면 그렇게.
- 앙코르는 지금처럼 앙코르 색, 메들리는 한 줄("메들리 n곡")로.
- 두 날이 같으면 "같은 세트리스트입니다."

### 지울 것·바뀔 것

- TourSetlistVersions·TourCommonSetlist의 접기(collapsible, defaultOpen=false)와
  "한 눈에 보기" 제목 — 투어 상세에선 안 쓴다(다른 곳에서 안 쓰면 정리).
- TourDateList의 아코디언(openId, TourDatePanel) — 투어 상세에선 고르기로. LiveSchedule(단독
  공연 상세)은 그대로 아코디언을 써야 하니, 날짜 줄·도시 머리 컴포넌트를 두 쓰임이 같이
  쓰도록 나눈다(펼침/고르기를 props로).
- docs/CONVENTIONS.md의 투어 상세 설명, README 기록.

## 구현자에게 맡긴 것

- 칼럼 비율, 페이지 최대 폭, sticky 위치·높이.
- 비교 창의 공연일 고르기 UI 모양, 두 칼럼 정렬 방식.
- 선택곡 자리 줄 도시 목록을 줄여 보일지.
- 해시 동기화를 훅으로 뺄지(예: `useHashSelection`) — 테스트는 해시 ↔ id 변환(순수 함수)에.

## 테스트

- 해시 값 ↔ 공연일 id 변환(같은 날짜 여러 공연일 `-2`, 모르는 해시, 취소된 날).
- 비교 매칭(추가·빠짐·순서 변경) — 기존 setlist-diff 테스트가 계속 통과하고, 날짜 두 개 비교
  케이스 추가.
- 비교 기본값(A·B) 고르기.
- 화면 확인은 사용자가 요청할 때만(브라우저 검증 기본 안 함 — 메모리 feedback_no_browser_verification).

## 개편 2 (2026-11-27) — 목록-상세 2단(시안 A)

첫 구현 뒤 사용자 피드백: 카드가 많고 모양이 제각각, 한 페이지 정보량이 많아 읽기 어렵고,
포스터 비율에 따라 머리 높이가 변한다. 구역마다 같은 제목 줄(LiveSectionHeader) + 카드
하나로 맞춘 뒤(개편 1), 레이아웃을 아래처럼 바꾼다(시안 A, 사용자 결정 — B 페이지 탭, C 1단
+ 일정 표는 고르지 않음).

- **머리 높이 고정**: 포스터는 3:4 고정 상자(PC 96×128px, 모바일 84×112px, 잘라 채움, 눌러서
  원본). 옆에 아티스트·제목(한/영). 티켓은 보딩 티켓 디자인 그대로 한 줄 띠(LiveTicket
  `strip` — 공연 종류 · 칸들 · 음원/X 아이콘을 한 줄, Variation·Official 줄 없음). PC는 띠가
  제목 아래, 모바일은 포스터 줄 아래 전체 폭.
- **왼쪽 = 고르는 목록(공연 일정)**: 제목 줄 "공연 일정 · n dates · 세트리스트 비교하기". 맨 위
  "투어 세트리스트" 항목(공통 세트리스트가 있을 때) + 도시 머리·날짜 줄(날짜·요일·DAY/회차·
  취소)만 — 선택곡 미리보기·곡 수·그림 없음. PC는 세로 목록(240px 안팎, sticky), 모바일은
  가로로 넘기는 밑줄 탭 한 줄("투어 세트리스트 | 오사카 04.20 | 04.21 | 나고야 04.27 …" —
  같은 도시가 이어지면 도시 생략).
- **오른쪽 = 고른 것 하나**: 투어 세트리스트(밑줄 판 탭 + 요약 한 줄 + 목록) 또는 그날
  세트리스트(제목 줄 "← 오사카 04.21", 날짜·공연장 한 줄, 썸네일 + 목록). 모바일도 같은 자리
  (시트 없음 — 개편 전 시트 결정을 대신함).
- **선택곡 자리 접기**: "선택곡 · n곡 ▾", 누르면 곡과 불린 도시.
- **공연 정보**: Variation·추가 이미지는 맨 아래 "공연 정보" 구역(둘 다 없으면 없음).
- **기본 선택**: 해시가 없으면 공통 세트리스트, 공통 세트리스트가 없으면 첫 공연일(취소 제외).
- 그대로: 주소 해시·뒤로 가기(historyStep), 비교 창(TourCompare), 단독 공연 상세(아코디언).
